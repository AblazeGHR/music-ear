# 开发路线图（ROADMAP）

> 基线：earpath-app v0.2.2（commit `f5241f5`，MIT），已导入本项目。目标：把 8 项产品需求做到"真实现、可验收"，保持零后端、零账号、纯静态、少依赖。

## 1. 功能差距总表

| # | 需求 | 现状 | 差距 | 归属里程碑 |
|---|---|---|---|---|
| ① | 绝对音准（无参考音辨音名） | ✅ 已实现（v0.3.0，4 关卡） | — | M1 完成 |
| ② | 相对音准/调内音级 | ✅ 已有（终止式 + 音级，solfège/数字可切） | 可后续补"小调扩展"类关卡（已有部分） | — |
| ③ | 音程听辨 | ✅ 已有（12 种 × 三方向 + 复合） | 无 | — |
| ④ | 和弦类型 | ✅ 已有（13 类） | 无 | — |
| ⑤ | 和弦转位 | ⚠️ 仅三和弦 1/2 转位 | 补七和弦转位（dom7/maj7/min7/m7b5 × 1/2/3 转位） | M3 |

## 2. 里程碑与验收标准

### M1 —— 绝对音准模块 + 最低测试基建 ✅ 已完成（v0.3.0，2026-10-13）

任务：

1. `js/curriculum.js` 注册新模块 `absolute`（kind: `choice`），关卡递进：自然音 7 音 → 12 音全名 → 跨八度（C2–C6）→ 5 个变化音专项；每关沿用 "window/need" 目标制（12/10）。引导路径同步接入（basics 解锁至第 3 关，experienced 全解锁）。
2. `js/engine.js` 新增 `genAbsolute`：随机单音（无任何参考音与调性上下文，与 degrees 模块严格区分）；选项为该关卡音名；`itemKey` 形如 `ap:<音级类>`（如 `ap:0`），判分按**音级类（pitch class）**比较，等音拼写沿用 `theory.js` 的 `NOTE_NAMES` 表。错误对比试听（`playOption`）在**题目所在八度**播放所选音名。
3. `js/views.js` 接入新模块：关卡页答案预览标签（音名而非编号）、统计页混淆对名称与回放按钮；`css/style.css` 新增模块配色 `--c-lime`。
4. 测试基建（**零依赖**，Node 内置 `node --test`）：`tests/theory.test.js`（频率换算、音程半音、和弦结构、转位音级集合不变式、音阶集合特征音、罗马数字、模块注册完整性）与 `tests/absolute-pitch.test.js`（关卡梯度、选项拼写、单音无参考、音域边界、判分与统计键）。
5. 最小 `package.json`（无依赖，仅 `type: module` + `test` 脚本）；应用本身仍是"仓库根目录即产物"。

验收结果：

- [x] 无参考音：题目仅含 1 个音频事件、`at=0`、无 cadence/drone 字段——由 `tests/absolute-pitch.test.js` 对 4 个关卡共 240 次生成断言；浏览器实操 2 题（一对一错）
- [x] 答错对比试听：错误反馈给出 "▶ Your pick / ▶ Answer"，按题目八度播放所选音名与正确音名
- [x] 统计接入：统计页出现 Absolute Pitch 行（逐关正确率）、混淆对显示"A heard as D"并可回放；localStorage 写入 `ap:<音级类>` 逐名次统计，计入连击与热图
- [x] `npm test`（= `node --test`）16 项全绿，无需浏览器、无第三方依赖
- [x] 关卡答案集与 `theory.js` 音名表一致（选项 id 为音级类整数，标签由 `pitchClassName` 派生，测试断言）
- [ ] **人工听感抽检**（留待用户）：确认真机听感与音域区间舒适度；此项无法由自动化断言替代

### M2 —— 音色引擎（合成音 + 钢琴采样切换）

任务：

1. `js/audio.js` 建立音色抽象：保持 `playEvents(events)` 对外接口不变，内部按 `state.settings.timbre` 选择合成器或采样器（sampler）。
2. 采样资源选型：**必须是许可清晰的钢琴采样**（候选方向：CC0 或 CC-BY 且完整署名；禁止使用 open-ear 样本——署名链不完整）。采样本地自托管（同仓库 `assets/samples/`），记录许可与署名于 `NOTICE.md`。
3. 设置页新增音色选择，`state.js` 持久化（含旧存档默认值合并，不破坏既有数据）。
4. `sw.js` 缓存列表纳入采样文件（离线可用）；音频加载失败时回退合成音色（**不作为借口跳过错误提示**，需日志与可见提示）。

验收标准：

- [ ] 设置中切换 synth/piano 即时生效于所有题型，刷新后保持
- [ ] 飞行模式下（SW 缓存后）钢琴音色可用；断网首访有明确降级提示
- [ ] 采样许可与署名在 `NOTICE.md` / README 中完整可查（含来源 URL、许可证名）
- [ ] `playEvents` 事件结构不变（既有测试不回归）；新增 timbre 选择逻辑的单元测试

### M3 —— 转位扩展 + 自定义训练

任务：

1. `theory.js` 增加七和弦转位数据（dom7/maj7/min7/m7b5 的 1/2/3 转位，voicing 一律以最低音为 0 的半音偏移表示，与现有约定一致）；`curriculum.js` 增加对应关卡。
2. 自定义训练：设置项增加
   - 音域档位（如 低/中/高，或按模块起止 MIDI 范围）；
   - 各模块/题型启用开关（关闭的模块不出题、不计入统计）；
   `engine.js` 所有生成器抽样时尊重音域边界（含边界内无法出题时的降级策略）。
3. 设置持久化与旧存档兼容（`state.js` 版本字段演进策略明确化）。

验收标准：

- [ ] 转位关卡出题/判分/对比试听正确（新增数据测试：每种转位的半音结构断言）
- [ ] 任意音域设置下连续 50 题不越界（测试断言生成器边界）
- [ ] 关闭某模块后：不出题、统计页不新增该模块数据
- [ ] 旧 localStorage 存档升级后不丢数据（提供迁移测试或手动验收脚本）

### M4 —— 工程收尾与发布

任务：

1. 静态部署 CI：GitHub Pages（或 Cloudflare Pages）自动发布根目录；**子路径部署适配**（核对 `manifest.webmanifest` 的 `start_url`/`scope`、`sw.js` 缓存路径、`index.html` 内相对/绝对路径）。
2. 清理上游遗留指向：`js/config.js` 的 `REPO_URL` / `FEEDBACK_EMAIL` 替换为本项目地址（或移除反馈入口）；`marketing/` 目录评估去留。
3. 品牌/命名决策（当前暂用 upstream 名 "earpath" 与工作名 music-ear）。
4. PWA 缓存版本策略：发布流程中 bump `sw.js` 的 `CACHE` 常量；编写发布检查清单。
5. 测试面扩展（引擎生成器、session 状态机）；可选引入 Playwright 冒烟（若保持零运行依赖，放 CI 侧）。
6. 更新 README（功能状态表）、隐私说明（离线/无遥测）。

验收标准：

- [ ] 推送 tag 后 CI 自动发布，线上站点可访问、可练耳（端到端冒烟）
- [ ] Lighthouse PWA 安装性通过；离线冷启动可用
- [ ] 仓库无任何指向上游个人账号的反馈链接
- [ ] 发布检查清单文档化（缓存版本、子路径、采样文件）

## 3. 风险与决策点

| 风险/决策 | 说明 | 处理 |
|---|---|---|
| 钢琴采样许可 | CC-BY 需署名、CC0 最省事但音质差异 | M2 开工前先定样本来源并写入 NOTICE；不可用许可不明样本 |
| 子路径部署 | 上游按根域名部署设计 | M4 前若用 `*.github.io/<repo>/`，需实测；必要时配置 CNAME/自定义域 |
| SW 缓存陈旧 | network-first 已缓解，但采样缓存大 | 采样不入预缓存列表，改为首次使用时缓存（stale-while-revalidate 策略） |
| localStorage 架构演进 | `earpath-v1` 无迁移机制 | M2/M3 修改 settings 时保持"深合并默认值"策略并加测试 |
| 上游分歧 | 本项目为 fork，将独立演进 | 保留 `upstream` git remote 便于比对；我们的变更记入 `CHANGELOG.md` 新增节 |
| 绝对音准的争议性 | 学界对成人绝对音准可训练性有争议；上游刻意不做 | 模块定位为"音名辨识练习"，文案如实、不承诺"训练出绝对音准" |

## 4. 非目标（明确不做）

- 账号系统、云同步、排行榜、社交、后端 API、数据库
- 商业化/订阅；花哨视觉特效
- 云端部署操作（本项目仅产出静态产物与 CI 配置；部署动作由用户执行）
